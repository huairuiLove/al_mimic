# 仓库架构重组方案

## 目标架构

采用标准 `src` 单命名空间，并保持唯一依赖方向：

```text
main.py                         # 唯一根启动器，只调用 al_mimic.cli
src/al_mimic/
├── cli.py                      # 所有任务、方法、数据、训练、评估的统一入口
├── core/
│   ├── contracts.py            # TaskPlugin、MethodPlugin、标准输入输出
│   ├── engine.py               # 通用主动学习轮次引擎
│   ├── capabilities.py         # task × method 能力检查
│   └── artifacts.py            # 统一实验产物 schema
├── tasks/
│   ├── registry.py             # 懒加载任务注册表
│   ├── mimic_iii/
│   ├── brset/
│   └── mds_ed/
├── methods/
│   ├── registry.py             # 懒加载方法注册表
│   ├── random/
│   ├── comal/
│   ├── mm_comal/
│   ├── modis/
│   └── mosaic/
├── utils/
│   ├── config.py
│   ├── fusion.py
│   ├── linear.py
│   ├── contrastive.py
│   ├── prototypes.py
│   ├── schedule.py
│   ├── runtime.py
│   └── io.py
└── evaluation/
```

严格执行以下边界：

- `core` 不导入具体任务或方法。
- 一个 task 不导入另一个 task，也不导入任何具体 method。
- 一个 method 不导入 task、runner 或 sibling method；只允许依赖 `core` 契约和 `utils`。
- `utils` 只放无任务/方法所有权的纯工具，不放 runner 回调或品牌化算法分支。
- 注册表保存导入路径并按选择懒加载，未选中的方法不会影响启动；删除一个方法目录后，其余方法仍可导入和运行。

## 1. 保护当前工作树

当前工作树已有大量用户修改和旧第三方目录删除。正式迁移前将：

1. 在现状上创建 `refactor/repository-architecture` 分支，不回退任何现有修改。
2. 在仓库外生成原始 refs 的 Git bundle、tracked diff 和非 `thirdparty/` 未跟踪源码清单/归档。
3. 第一项实际编辑先将 `/thirdparty/` 整体加入 `.gitignore`，避免约 21 GB 本地第三方代码、环境、模型或临床数据被误暂存。
4. 后续只暂存明确属于本次重组的文件；不会删除本机 `thirdparty/` 目录内容。

## 2. 建立稳定的插件契约

用显式数据结构替换当前 `experiment: Any` 加 `_acquire_*` 私有回调：

- `TaskPlugin` 声明任务 ID、query unit、支持的 action、数据准备/验证、模型训练、query-level 输出聚合、评估和产物写入。
- `MethodPlugin` 声明所需能力，如 probabilities、features、modality tokens、validation reference、group IDs，以及方法训练生命周期和 `acquire()`。
- `RoundOutputs` 统一包含 query IDs、labels、probabilities、features、modality tokens、group IDs 和任务元数据。
- `AcquisitionResult` 统一返回真实 query IDs、诊断信息和 score summary，不再假定 ID 一定是 `int`；BRSET 的 patient string ID 成为正式契约。
- 通用 engine 负责 schedule、冷启动、轮次状态、checkpoint、最终评估和恢复；task 负责数据/模型，method 负责辅助训练及采集逻辑。

CoMAL、MM-CoMAL、MoDIS 的辅助训练通过通用 lifecycle hook 接入 task trainer，task 只调用协议，不出现策略名分支。MoSAIC 和 Random 使用同一协议但无需辅助优化器。

## 3. 严格迁移方法代码

- 将顶层 `modis/` 迁入 `src/al_mimic/methods/modis/`。
- 将顶层 `mosaic/` 迁入 `src/al_mimic/methods/mosaic/`。
- 从 `mimic_comal/model.py`、`multimodal_training.py` 和两个 runner 中抽出 CoMAL/MM-CoMAL 模型、contrastive training、prototype 更新和 acquisition scoring，分别形成独立插件。
- `comal` 与 `mm_comal` 不互相导入；可复用的对比损失、prototype 数学和通用表征组件放入有明确职责的 `utils` 模块。
- 将 `mosaic.tokens` 中的 `fuse_token_batches`、`probabilities_from_fused`、`augment_bias` 拆到 `utils/fusion.py` 和 `utils/linear.py`，彻底删除 `MoDIS -> MoSAIC` 依赖。
- 方法注册采用懒加载，单个方法缺失时只在用户选择它时报告错误。
- Mixup 明确归为 MIMIC-III task 的训练 augmentation，不冒充 acquisition method，也不进入全局方法注册表。

## 4. 规范任务包

### MIMIC-III

将 `mimic_comal/` 按职责迁到 `tasks/mimic_iii/`：

- Yang-Wu classifier、HDF5 store、MIMIC metrics、task specs、scenario 和 visualization 保留在任务包。
- diagnoses、phenotyping-25、CCS-172 作为同一 task family 下的 task profiles，而不是靠配置文件名推断。
- 数据准备代码放入 `tasks/mimic_iii/preprocessing/`，消除裸模块导入和 `sys.path` 修改。
- 删除原始 CoMAL 源码 hash 校验链；实验 provenance 改为当前仓库 commit、resolved config、数据 manifest 和论文/上游 URL。

### BRSET

将 `brset_al/` 迁到 `tasks/brset/`，删除所有 `mimic_comal.*` 导入。

- classifier 仍在 image level 训练。
- 进入任何 acquisition method 前，统一将输出聚合为 patient query level。
- CoMAL prototype、MoDIS probe/prevalence、MoSAIC Fisher reference 都在 patient-level canonical outputs 上拟合和评分，避免患者图像数造成隐式加权。
- MoSAIC 使用独立 validation reference，不再把 labeled outputs 同时当 reference。
- 为 Random、CoMAL、MM-CoMAL、MoDIS、MoSAIC 增加相同 synthetic patient-level integration contract；只有通过的组合才由 capability matrix 对外声明支持。

### MDS-ED

将当前经过项目修改且实际需要的 MIT 许可实现迁成 `tasks/mds_ed/` 第一方维护代码：

- 数据 release audit、ECG 目录发现、可恢复 waveform 转换、memmap validation、低内存 CSV 加载、fold/首个 ECG 评估规则、S4 + tabular 模型和 supervised training 均改为包内相对导入。
- 保留 MIT copyright/license 和衍生实现说明到根级 notices 文档。
- MDS-ED 初期明确支持 `prepare`、`validate-data`、`train`、`hardware`，不虚报主动学习方法支持；传入 `--method` 时统一入口直接拒绝。
- MDS-ED 重依赖放入 `pyproject.toml` 的可选 `mds-ed` extra；未安装时不影响 MIMIC/BRSET 和方法注册。

## 5. 统一配置和入口

重组配置为：

```text
configs/
├── tasks/{mimic_iii,brset,mds_ed}/
├── methods/{random,comal,mm_comal,modis,mosaic}.yaml
├── scenarios/
└── experiments/<task>/<profile>.yaml
```

- task profile、method profile、scenario 和 experiment override 合并后只校验一次。
- CLI 的 `--task`、`--method` 必须与 resolved config 一致；不再根据文件名猜 task，也不再只覆写 `strategy` 而保留错误实验名或错误方法参数。
- 统一所有路径相对于配置根/项目根的语义，消除 MIMIC cwd 相对与 BRSET config 相对的不一致。
- `main.py` 成为唯一薄启动器，正式入口为 `al-mimic = al_mimic.cli:main`；删除 `mimic-comal`、`brset-al` 和旧包导入接口。
- CLI 提供 task/method 列表、capability matrix、prepare、validate-data、active、full-data/train、visualize、matrix 等明确子命令；每个 task 对不支持的 action 给出确定错误。
- 删除当前声明却没有实现的模糊 `train` 路径，改为只有声明 supervised training capability 的任务可执行。

## 6. 第三方与数据处理彻底解耦

- `/thirdparty/` 只作为本机人工查阅目录，父仓库整目录忽略，不包含任何被跟踪 README。
- 删除 `.gitmodules` 和嵌套 VCS mapping；IDE 排除整个目录。
- 删除生产、测试和脚本中的 `thirdparty`/`third_party`/`CoMAL-main`/`MDS-ED-main` 路径、动态源码加载、子进程执行和 `sys.path` 注入。
- MIMIC phenotyping 所需且许可允许的最小 preprocessing 逻辑迁成第一方模块；无法确认许可的 CCS 定义不复制，改成有清晰 schema 的显式外部数据输入。
- FIDDLE/Yang-Wu legacy resume/full-pipeline 入口退役；正式 preprocessing 只接受原始数据或已定义 schema 的中间 artifact，不执行参考源码。
- 根级 `THIRD_PARTY_SOURCES.md` 仅记录论文、来源 URL、版本和人工对照方式；代码中不依赖该目录。

## 7. 测试、脚本和产物

所有测试统一放在标准 `tests/` 下：

```text
tests/
├── architecture/
├── unit/{core,utils,tasks,methods}/
└── integration/
```

重点新增：

- AST import-boundary 测试：禁止 task 互导、method 互导、method 导入 task、任何运行代码引用 thirdparty。
- 每个方法独立导入测试，特别保证没有 MoSAIC 时 MoDIS 仍可导入和运行。
- task × method capability 和统一 acquisition contract 测试。
- BRSET patient-level 聚合、prevalence 和 validation-reference 回归测试。
- MDS-ED release/memmap 合成 fixture 与 CLI dispatcher 测试。
- 输出 schema、恢复状态、evaluation matrix、wheel package discovery 和 console entrypoint 测试。

脚本按 `scripts/data/`、`scripts/experiments/`、`scripts/evaluation/` 分类，只调用统一 CLI 或正式包 API；删除硬编码 `/root/...` 和手工改 `sys.path`。实验目录规范为 `experiments/<task>/<profile>/<method-or-supervised>/<scenario>/<seed>/`，保留关键 `final_metrics.json`、`final_predictions.npz` 字段兼容并加入 schema version。

## 8. 打包、文档与清理

- 项目名改为通用的 `al-mimic`，setuptools 只从 `src` 发现 `al_mimic*`，删除 stale `egg-info`。
- README 重写为架构、统一 CLI、能力矩阵、添加 task、添加 method、数据边界和实验产物说明。
- 更新所有 base-task 文档、shell scripts 和配置路径。
- 删除 `mimic_comal/`、`brset_al/`、顶层 `modis/`、`mosaic/`、旧 adapter、旧 task CLI 和兼容 wrapper；按用户选择不保留 shim。

## 9. 验证与 Git 历史清理

代码阶段依次运行：

1. `ruff check`。
2. 完整 `pytest`，包括架构、单元和轻量 synthetic integration。
3. build wheel，并在隔离环境中验证只从安装包导入和运行 `al-mimic --help/tasks/methods`。
4. 对本机存在的数据运行只读 contract audit；GPU/重依赖不可用时明确记录未执行的真实训练，不用 synthetic 结果冒充正式实验。
5. 扫描源码、测试、脚本、配置，确认运行路径零 thirdparty 引用。

全部通过并完成本地迁移提交后，才执行历史重写：

- 先生成最终 Git bundle 备份。
- 用 `git filter-repo` 从所有 refs 清除 `CoMAL-main/`、`MDS-ED-main/`、`third_party/`、`thirdparty/`、旧 `.gitmodules` 和原始 CoMAL hash 清单。
- 验证 `git log --all -- <第三方路径>`、`git ls-files` 和对象扫描均无第三方内容。
- 恢复被 `git filter-repo` 移除的 origin URL，但不执行 push。

历史重写只在本地完成。远端强推属于单独的外部破坏性操作，本次不会自动执行。
